## Контрольные вопросы

1. **Чем git stash отличается от git commit?**  
   Stash временно убирает незакоммиченные изменения в специальное хранилище и не добавляет их в обычную историю коммитов. Commit сохраняет изменения как постоянную точку истории проекта.

2. **Чем git rebase отличается от git merge? Когда какой использовать?**  
   Merge объединяет истории веток и обычно создаёт отдельный коммит слияния. Rebase переносит коммиты одной ветки поверх другой, переписывая их и формируя линейную историю. Rebase удобен для личных веток, merge — для объединения совместной работы.

3. **Что такое git tag и зачем он нужен?**  
   Tag — неизменяемая метка конкретного коммита, например v1.0. Она помогает обозначать версии проекта и возвращаться к нужному состоянию.

4. **Чем git fetch отличается от git pull?**  
   Fetch загружает новые данные с удалённого репозитория, но не меняет текущую ветку и рабочие файлы. Pull загружает изменения и сразу объединяет их с текущей веткой.

5. **Что произойдёт, если сделать rebase в общей ветке?**  
   История общих коммитов будет переписана, из-за чего у других участников могут появиться дублирующиеся коммиты и конфликты. Поэтому rebase обычно используют в личных ветках.

6. **Как отправить тег на GitHub?**  
   Командой `git push origin v1.0`. Обычный `git push` не всегда отправляет теги автоматически.

## Примечание о выполнении Git-команд

Операции с файлами и историей GitHub выполнены в удалённом репозитории. Команды `git stash`, `git fetch` и `git pull` относятся к локальному клону: stash хранится только локально, а fetch/pull выполняются из локального Git. Поэтому факт их локального выполнения должен подтверждаться терминалом на компьютере, а не только изменениями на GitHub.
